# Modo Jam — plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Salas de escucha compartida para Spotaple: cola común, reproducción en la PC del admin o en todas, votos para saltar y likes, por red local o por un relé en internet.

**Architecture:** Un motor de sala puro y sin dependencias (`src/shared/jam/`) corre igual en dos hosts: un servidor `ws` dentro del proceso main del admin (red local) y un Worker + Durable Object de Cloudflare (internet). El cliente WebSocket vive en main y empuja el estado al renderer por IPC; en el renderer un "conductor" (`jam-sync`) maneja el reproductor existente con una cola de un solo ítem.

**Tech Stack:** TypeScript, Electron 45 (Node 24, `WebSocket` global), `ws` (nueva), React 19 + zustand, vitest, Playwright (e2e), Cloudflare Workers + Durable Objects (`wrangler`).

**Spec:** `docs/superpowers/specs/2026-11-05-jam-mode-design.md`

## Global Constraints

- `PROTOCOL = 1`. Topes: 30 miembros, 200 ítems de cola, nombre de 1 a 24 caracteres.
- Código de sala: 5 caracteres del alfabeto `23456789ABCDEFGHJKMNPQRSTUVWXYZ` (31 símbolos, sin 0, O, 1, I, L).
- Invitación: Internet = `K7M2P`; Red local = `ip:puerto/K7M2P`. Puerto local por defecto 47800 (si está ocupado, uno libre). Ruta WebSocket: `/<CODIGO>` en ambos hosts.
- Admin = quien crea la sala. Gracia del admin desconectado: 60 000 ms. El traspaso al miembro conectado más antiguo ocurre solo en Internet; la sala local termina con el admin.
- Saltar: los votos de miembros conectados deben ser más de la mitad (`floor(conectados / 2) + 1`); el admin y quien pidió la canción saltan directo.
- Like: solo sobre la canción que suena, una vez por miembro, suma a quien la pidió; no toca favoritos.
- Sin duplicados en la cola (mismo `track.id` en la cola o sonando). Modo por defecto: `admin-only`.
- Sincronía: se corrige con seek cuando el desvío supera 0,5 s, revisando cada ~5 s. Offset de reloj: ~5 muestras ping/pong, se elige la de menor RTT, se repite cada ~30 s.
- Relé: la sala se borra tras 6 h sin actividad. URL por defecto en `src/shared/jam/config.ts`, sobrescribible con `SPOTAPLE_JAM_RELAY`.
- Nunca viaja audio entre PCs. La CSP no se relaja (`connect-src 'self'`): toda la red del jam va por el proceso main y el renderer solo usa el puente.
- Ajustes en la tabla `settings` (`store.getSetting` / `store.setSetting`): `jam_member_id`, `jam_name`, `jam_last_mode`. Sin tablas nuevas.
- Textos de interfaz en español rioplatense (voseo). La interfaz mantiene los niveles de accesibilidad actuales (`npm run a11y` debe seguir pasando).
- Verificación estándar: `npm test`, `npm run typecheck`. Pruebas nuevas en `tests/*.test.ts` (vitest, entorno node).

## Decisiones del plan que no están en el spec

- El Durable Object usa WebSockets normales (`accept()`), no hibernables: el estado vive en memoria y la sala termina si el objeto se evacúa. Es más simple y alcanza para ≤30 personas; subir a hibernación con estado persistido solo si se agota el plan gratuito.
- Si el admin elige "Salir" no hay gracia: Internet traspasa el rol de inmediato; Red local cierra la sala. La gracia de 60 s es solo para desconexiones.
- Los miembros desconectados que no son admin se conservan 10 minutos (para recuperar votos y likes) y luego se quitan; sus ítems de cola se quedan.
- Tras 3 fallos `unavailable` seguidos la sala queda `halted` (sin canción actual, cola intacta); lo destraba una acción del admin ("siguiente" o "reproducir ahora").
- `queue.add` lleva `at?: 'end' | 'next' | 'now'`; solo el admin puede usar `next` y `now`.
- En una sala, "Reproducir" sobre una lista pide solo la canción elegida; "Agregar a la cola" pide todas.
- El audio del admin es la verdad: si su posición real se desvía más de 1,5 s de la anclada, el conductor reancla con `transport seek`.
- Reconexión del cliente con espera de 0,5 / 1 / 2 / 4 / 8 s (tope 8 s). Se descartan mensajes inválidos y se cierra la conexión tras 20; límite de 30 mensajes por segundo.

## Review Focus

Entradas o condiciones que el spec implica pero que ninguna prueba "feliz" cubre; cada una tiene su prueba en la tarea indicada.
1. Misma persona conectada dos veces (reinicio antes de que caiga el socket viejo): debe quedar un solo miembro y la conexión nueva reemplaza a la vieja (Task 7).
2. `ended` repetido, tardío o de otro ítem: no debe saltar dos canciones (Task 6).
3. Invitación pegada con espacios, minúsculas, `ws://`, `http://` o un nombre de equipo en vez de IP: se normaliza o se rechaza con mensaje claro (Task 2).
4. Canción con campos enormes, faltantes o miniatura que no es https: se rechaza sin tocar la sala (Task 3).
5. El admin se reconecta a mitad de canción: la canción no se reinicia ni se pierde la cola (Tasks 6 y 12).
